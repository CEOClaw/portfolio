## Multi-Agent AI Coordination
**Context: CEOClaw — working collaboration and continuing development**

Sean directs a team that has demonstrated asynchronous collaboration through GitHub:

- **Sean** — priorities, business judgment, and approval of consequential actions.
- **Chat / ChatGPT** — strategy, architecture, specifications, implementation support, and review.
- **Chief / GrokBot** — intake, triage, research, coordination, and follow-up.
- **CEOClaw / OpenClaw** — operations, infrastructure, runtime execution, and continuity.
- **Patriot / Hermes** — infrastructure testing, local-model experiments, and assigned research.

### Demonstrated workflow

- Agents contribute signed comments to a shared issue discussion.
- Tasks identify an accountable owner and expected deliverables.
- Workflow labels distinguish readiness, execution, blockers, and review.
- Shared decisions and evidence are retained outside individual chat histories.
- Important changes can be proposed through branches and pull requests.

[Team introductions and collaboration evidence](https://github.com/CEOClaw/Central/issues/4) *(access required if private)*.

### Design principles

- One accountable owner per active task.
- Selective retrieval of relevant knowledge.
- Verification before claiming completion.
- Separate permission to read, propose, merge, deploy, spend, or communicate externally.
- Preserve client and organizational boundaries.

**Tools used across the work:** OpenClaw, Hermes, ChatGPT, GrokBot, Docker, GitHub, Markdown, and Obsidian. Capabilities vary by runtime and connection; a shared task board does not itself establish automatic monitoring or a response-time guarantee.

## Shared Institutional Memory
**Context: CEOClaw — verified GitHub / Obsidian workflow**

A model-independent knowledge approach separates:

- **Durable knowledge:** Markdown records versioned in Git.
- **Human interface:** Obsidian over a local repository clone.
- **Task coordination:** GitHub issues, comments, and review.
- **Working memory:** context specific to an individual agent or session.

The documented round trip includes an agent-created branch and pull request, human review and merge, a local Obsidian edit committed back to GitHub, and independent retrieval of that edit.

The purpose is continuity: another approved agent should be able to find the relevant decision, current state, and next action without inheriting an entire conversation.

## On-Chain Analytics and LP Forensics
**Context: digital-asset analysis and tooling**

Work described in this portfolio includes analysis of Uniswap V3 liquidity positions, transaction histories, and wallet relationships.

### Analysis methods

- Trace position NFTs and reconstruct transfer history.
- Parse liquidity and fee-related events.
- Reconcile fee flows and position-management activity across wallets.
- Investigate potential relationships among delivery, liquidity-management, and fee-collection addresses.

### Tooling approach

- Blockchain explorer API wrappers.
- Transaction-level event parsing for Transfer, Collect, Mint, and Burn events.
- Cross-wallet analysis and evidence-linked reporting.
- Workflow: wallet → positions → fee flows → counterparty analysis.

Wallet clustering is an analytical hypothesis unless corroborated; transaction evidence alone does not establish beneficial ownership.
